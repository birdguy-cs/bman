# CLAUDE.md

Project context for AI assistants working on **bman**, a single-button music player in Rust for a Raspberry Pi Zero 2 W with a PiSugar Whisplay HAT (240x280 ST7789 screen) and a PiSugar 3 battery. It can also run on a PC in a `minifb` window for testing. See `README.md` (quick start) and `DOCS.md` (full user docs; keep it updated when behaviour changes).

## Working notes

- The owner is not a Rust beginner but prefers short, direct answers and working code over explanations. Casual tone is fine.
- **Don't assume code was compiled.** Much of this was written in a sandbox with no Rust toolchain. Run `cargo build --release` and fix errors before building more on top.
- Keep the AI usage notice at the top of `README.md`.
- `music` (symlink), `videos` and `config.txt` are gitignored on purpose. Don't commit them.
- Rust edition 2024. Main crates: rodio 0.23 (symphonia-all), symphonia (aiff, pcm), rppal 0.22 (GPIO, PWM, SPI), minifb, font8x8, lofty 0.25, image 0.25 (jpeg/png/bmp/webp), ctrlc, zbus 5, ureq 3 (rustls), quick-xml 0.41 (podcast RSS), serde_json 1 (podcast / LibriVox search), sha2, libc (termios for the terminal driver), alsa 0.11 (system volume mixer; same version cpal uses), zip 9 (deflate only; unpacks Deno), openh264 0.9.9 (music videos).
- **Portability.** Must work on any Linux distro regardless of init system (only `autostart.rs` knows about init systems; `root.rs`/`power.rs` call `sudo`, `reboot`, `poweroff`, by the owner's choice; USB transfer's root-owned boot script uses `modprobe`/`mount`). No external commands, no distro-specific paths. Runtime deps: libasound + libc only. Prefer pure-Rust crates over C libraries. Exceptions (owner's choice): OpenH264 (`openh264` crate, C++ compiled from source and linked statically, no runtime dep; builds need a C++ compiler, the workflow installs `g++-<cross>` and sets `CXX_<target>`) for music videos; `streaming.rs` runs yt-dlp + Deno, opt-in, downloaded by bman itself into `tools/` (and `python3` for the yt-dlp zipapp when 3.10+ is there).

## Architecture

| File | Role |
|---|---|
| `main.rs` | `App` state, navigation stack, button handling, idle timeout, background library rescan, main loop |
| `render.rs` | `Framebuffer`, `Display` trait, `GUI` enum, `View`/`Style`, all drawing, colour-scaled dimming |
| `display_driver.rs` | `DRIVERS`, `create_display`, `WindowDisplay` (PC test window; mouse and keys act as the button, minifb `InputCallback` for typed text) |
| `terminal.rs` | Terminal display driver (`driver=terminal` or `--driver terminal` = terminal only; `--terminal`/`-t` = `Mirror` in display_driver.rs: config driver + terminal, falls back to terminal only if the config driver fails): truecolor `▀` half blocks, box-filter shrink (fractional `SCALES`) to fit, `-`/`+` zoom and `0` fit (zoom past the window crops), diffed cell redraw, raw termios via `libc`, keys map straight to `Button`s (`buttons::key_button` shared with the window); on `GUI::TextInput` main calls `Display::set_typing(true)` and keys come back as `Typed` (char/erase/enter) from `poll_typed`, stderr dup2'd to `bman.log` while active |
| `whisplay.rs` | ST7789 driver over SPI0, backlight (software PWM), RGB status LED (`Display::set_led(Led)`, main's `App::led()` picks the colour each frame: red powering off > blinking red 5 s after `show_error` > green/blue alternating while installing an update > blue playing/stream loading > green) |
| `battery.rs` | `BatterySource` drivers (`auto`, `none`, `sysfs`, `pisugar`) in the `BATTERY_DRIVERS` registry, `BatteryMonitor` background thread (live-swappable) |
| `buttons.rs` | `PressCounter`, GPIO button thread with wiring auto-detect |
| `sched.rs` | `background()` = nice 19 for the calling thread (every background `thread::spawn` calls it first); `audio()` = best-effort SCHED_FIFO 10 or nice -10 (GPIO timing thread) |
| `audio.rs` (MP4 note) | MP4-family files (.m4a/.m4b/.mp4/.aac) decode through `TrackDecoder` (own Symphonia reader, first audio track's packets only) because rodio's decoder feeds every track's packets to the codec and stops at an m4b's second chapter (chapter text track). `play_from` = `play_from_speed(.., 1.0)` |
| `audio.rs` | `AudioPlayer`: rodio path (`use_system_audio=true` / wireless) or GPIO PWM path. Both read from `Prefetch` (decoder thread ~1.5 s ahead in a bounded channel; frames of silence on underrun, never blocks). rodio sink opened with an 8192-frame buffer (default 50 ms is too tight on a Pi Zero), falls back to default |
| `spoken.rs` | Podcasts + audiobooks (menu rows 7, 8; `GUI::{Podcasts, Show, PodcastResults, Audiobooks, Book, BookResults}`, all drawn from main's `spoken_view()` (title, status, rows) and handled in `spoken_button`). Folders `podcasts/`, `audiobooks/` beside music (`Library.shows` / `Library.books` via `scan_shows` / `scan_books`; USB tops too). `is_spoken(path)` = path has a podcasts/audiobooks component: then `play_from_speed(config.spoken_speed)`, NP 2/3 = +30/-15 s (`seek_spoken` reopens at the position), 5 = `cycle_speed` (`SPEEDS`), on_track_end marks done and plays on in order (no loop modes). `Progress` = `progress.txt` (`path\tsecs\tdone\twhen`), saved every 15 s, on switching (`save_spoken_position` uses `App.spoken_playing`, not the queue, which may already be replaced) and at exit before `player.stop()`; `resume_at` = saved - 2 s; within 30 s of the end = done; `last_of` picks a book's resume point by newest `when`. Feeds: `podcasts/feeds.txt` URLs; refresh (90 s after start, every 6 h, or the row) writes `<show>/.feed` + `.episodes` (`date\tguid\ttitle\turl\tfile`), downloads the newest unplayed episode; RSS via quick-xml (entities come as `GeneralRef`). Search: iTunes Search API (`media=podcast`, `feedUrl`), LibriVox API (`title=^` and `author=^`, `extended=1` sections' `listen_url`). One download thread (`.bman-download-*` then rename, purged at start); `spoken_wait` plays an episode once downloaded. M4B chapters: Nero `chpl` or QuickTime `tref/chap` text track (own box reader). Audible: owner asked; declined (DRM), docs point to DRM-free shops (Libro.fm) + USB |
| `stretch.rs` | WSOLA time-stretch for spoken speed: 30 ms Hann frames, 50% overlap, ±10 ms similarity search on a decimated mono mix (coarse every 4th offset, then fine). Applied in `Prefetch`'s decoder thread when speed != 1; positions = output time x speed |
| `library.rs` | Scanner (singles, albums, artists, playlists, and `Library.videos` from `videos/` beside the music folder: `root.with_file_name(VIDEOS_DIR)`, recursive, named like singles), `.m3u` read/write |
| `art.rs` | Cover art loader on a thread, 96x96 |
| `network.rs` | Wi-Fi via NetworkManager over D-Bus (`zbus`): list/scan, connect (password or saved), forget, radio on/off, IP; `wifi=` config lines imported at startup |
| `bluetooth.rs` | BlueZ over D-Bus (`zbus`, pure Rust): device list, scan, pair (own `NoInputNoOutput` agent), connect; background polling emits Connected/Disconnected events |
| `update.rs` | Self-updater: tag from the `github.com/<repo>/releases/latest` redirect (no API, no rate limit; repo from Cargo.toml `repository`), checks every 60 s, downloads `bman-<target>` + `.sha256`, verifies, renames over `current_exe()`, main loop exits and `exec`s the new binary. Releases built by `.github/workflows/release.yml` on `v*` tags (Debian 12 container, glibc 2.36, x86_64/aarch64/armv7 gnu) |
| `autostart.rs` | Start on boot. The one deliberate exception to init-agnostic: detects from `/proc/1/comm` then /run marks: systemd, OpenRC, runit (Void/Artix/Devuan layouts), dinit, sysvinit/Slackware (marked `rc.local` block); writes a service (marker comment) + enable symlink, no init commands; needs root: when not root it re-runs itself via `sudo -n`, then `sudo -S` with the password from the keyboard (`bman --autostart on|off --user --uid --dir`, handled by `autostart::cli()` at the top of `main`); passwordless `doas` fallback. Besides `streaming.rs` (yt-dlp/Deno), the only place bman runs another program |
| `root.rs` | sudo helper shared by autostart and power: re-runs own binary as `sudo -n` / `sudo -S` (password on stdin) with `--autostart ...`, `--power ...`, `--rfkill ...` or `--usb on ...`, dispatched by `root::cli()` at the top of `main`; reads back `OK msg` / `ERR msg`; `RootError::{NeedsPassword, WrongPassword, Failed}` |
| `rfkill.rs` | Reads `/sys/class/rfkill/*/{type,soft,hard}`; soft blocks lifted via root helper `--rfkill bluetooth|wlan` (writes `soft`=0). Bluetooth: silent `sudo -n` try at startup, prompt when Bluetooth screen opens / Scan; Wi-Fi: only when switching Wi-Fi on (NM's off can be an rfkill block, so never auto) |
| `power.rs` | Restart / shut down: logind then ConsoleKit2 `CanReboot`/`Reboot(false)` over zbus (no root needed in an active session), else root helper (`--power reboot|poweroff --user NAME`) installs `/etc/polkit-1/rules.d/50-bman-power.rules` (only that user, only login1/ConsoleKit reboot/power-off actions) then runs `reboot`/`poweroff`; next time logind says yes. Start on boot installs the rule too. Deliberately not a NOPASSWD sudoers entry (the bman binary is user-writable) |
| `mixer.rs` | System volume via ALSA mixer on `default` (prefers `Master`), opened fresh per call; `config.system_volume: Option<u8>` re-applied at startup (retries) and ~2 s after BT connects (applied twice to beat WirePlumber's restore) |
| `config.rs` | `config.txt` load/save (atomic temp-file rename) |
| `main.rs` (startup) | `ensure_layout()` right after `load_conf()`: creates `config.txt` (defaults), `music/`, `videos/`, `podcasts/` + `feeds.txt` (comment header), `audiobooks/` when `symlink_metadata` says nothing is there (never replaces a symlink, even a dangling one). Owner wants everything the app needs created at runtime; keep it in sync when adding folders/files that are required (on-demand data files like progress.txt don't need it) |
| `usb.rs` | USB transfer (Settings > System row 6, `config.usb`, on by default: owner wants plug-in-and-it's-there; open to any computer, owner's choice: MTP can't tell computers apart, so no trusted list). Gadget `/sys/kernel/config/usb_gadget/bman` (1d6b:0104), one FunctionFS function `ffs.mtp` mounted at `/run/bman-mtp`. Root part = root-owned boot step (owner's choice over passwordless sudo): one-time `bman --usb on [--uid --gid]` (SUDO_UID/GID default; `RootJob::Usb { prompt }`, silent `sudo -n` at startup, queued in `usb_setup_pending`) adds `dtoverlay=dwc2,dr_mode=peripheral` to config.txt if no `[all]`/unsectioned dwc2 line (stock has one under `[cm5]`), writes `/usr/local/sbin/bman-usb-gadget` (sh: modprobe, mount configfs + functionfs uid/gid, mkdir gadget, chown mount + `UDC`), installs boot service `bman-usb` via `autostart::install_boot_step` (systemd oneshot Before=bman, OpenRC, runit, dinit, rc.local block), runs the script once. `--usb off` removes it all (install.sh --uninstall). bman (as the user) writes descriptors (class 6/1/1, bulk IN ep1, bulk OUT ep2, intr IN ep3; FS+HS) and strings to ep0, binds by writing the UDC name; Off = unbind (ep0 stays open for the process lifetime); `poll_usb` re-checks `ready()` every 3 s until started. ep0 thread: ENABLE/DISABLE, class requests (Cancel, GetDeviceStatus). Tested with dummy_hcd + libmtp on the PC and on the Pi |
| `mtp.rs` | MTP responder over a `Transport` trait (unit tests use a fake host). Top folders Music/Videos/Podcasts/Audiobooks map to `music/`, `videos/`, `podcasts/`, `audiobooks/` (passed in by main's `start_usb`); handles assigned per path; uploads to `.bman-upload-<name>` then renamed; drops on the root go to Music (Videos by extension); tops can't be deleted/renamed/moved. Ops: device/storage info, handles, info, get (partial), delete, send info/object, move, copy, device prop D402, object props (list/desc/value/set name). Data phases in 64 KiB writes + ZLP when a whole number of packets; `Status { changed, busy, cancel }` shared with main (rescan on `changed`) |
| `video.rs` | Music videos and local videos (`videos/` folder, `GUI::Videos`, menu row 6; `App.video` keyed by the queue path, opened in `play_index_from` for `is_video_file`): own minimal MP4 reader (`mp4`: only moov + moofs read into memory, frames read from disk as decoded; avcC from moov, samples from stbl tables (stts/ctts/stsz/stsc/stco/co64/stss) for ordinary .mp4/.m4v/.mov or from moof/traf/tfhd/tfdt/trun for fragmented; first elst edit applied), OpenH264 with `Flush::NoFlush` (flushing per frame breaks B-frames), frames come out in display order so the n-th gets the n-th smallest pts; decoder thread 3 frames ahead in a sync_channel, late frames decoded but not converted; `Video::frame(audio_pos)` picks the due frame, a >3 s jump reopens at the keyframe before. YUV->RGB BT.601 nearest-scaled into 240x135. rodio's `total_duration` is wrong for files with a video track (uses the default/video track's frame count), so `audio.rs` takes the length from `video::duration` (mvhd) for video files |
| `streaming.rs` | Streaming menu. YouTube Music via yt-dlp (zipapp under `python3` if 3.10+, else standalone binary) + Deno (`--js-runtimes deno:tools/deno`), downloaded from their GitHub `releases/latest` into `tools/`, SHA-256 checked, Deno unzipped with the `zip` crate, then a test search + `--simulate` stream; `yt-dlp -U` daily. Search = flat `music.youtube.com/search?q=...#songs` (titles only). Songs download whole (`-f 140/bestaudio[ext=m4a]`, DASH m4a decodes fine, + webp thumbnail) to `temp/<id>.m4a`; queue `Song.path` is that path (`id_of` detects streamed songs). One download at a time in its own process group; a "play now" fetch kills a prefetch. Files kept only for current + next song; `temp/` purged at startup and exit. Liked songs: own list in `liked.txt` (`id\ttitle`, titles upgraded to "Artist - Title" from download metadata), `App.stream_to_liked` makes 5 on a result like instead of queue; account likes = flat `youtube.com/playlist?list=LM` with `--cookies youtube-cookies.txt` (chmod 600, only used for that list), saved to `youtube-likes.txt` on every successful load and shown from there at startup / offline / when the cookies are missing or expired. `youtube-cookies.py` (repo root, stdlib Python, run on the PC) writes that file from Firefox's `cookies.sqlite` (`--login`: throwaway profile under ~ via `firefox --no-remote --new-instance --profile`, user signs in and closes it, exported then deleted, so no browser ever rotates that session; bman's `bman-yt-likes` thread reloads likes every 6 h (first after 3 min) to keep it used, yt-dlp saves renewed cookies back) (copied first; expiry is ms in Firefox 13x+; skips container/partitioned cookies), `--to user@host` scps it. `GUI::StreamResults { list: StreamList }` shows all three lists. x86_64/aarch64 only (no 32-bit Deno) |

Drivers are pluggable: display (`driver=` key) and battery (`battery=` key). Display: implement the trait, add the name to the list, add a match arm in `create_display`. Battery: implement `BatterySource` and add a `(name, constructor)` entry to `BATTERY_DRIVERS` (first entry is the default; the Settings row cycles through the list).

## Releases

- `install.sh` (installer, POSIX sh, curl|wget, sha256 check, writes `~/start-bman.sh`, installs the polkit power rule via sudo unless logind already says yes or `--no-sudo`, saves itself as `~/bman/install.sh`; `--uninstall [--purge]` undoes it all, asking via /dev/tty before deleting music; keep its polkit rule text in sync with `power.rs`) and `start-bman.sh` live in the repo root and are attached to every release by the workflow, so `releases/latest/download/install.sh` works. Keep the start script inside `install.sh` in sync with `start-bman.sh`.

- `cross-build.sh [aarch64|armv7|x86_64]` (repo root): the release workflow's build in a `debian:bookworm` container (podman or docker) on the PC, into `dist/` (gitignored); cargo/rustup cached in volumes, target in `target/debian`. A plain cross compiler on the PC would link against its newer glibc and not run on the Pi (2.36). Test loop: `./cross-build.sh && python3 update-pi.py bman@<pi> --file dist/bman-aarch64-linux-gnu`.
- `update-pi.py` (repo root, stdlib Python + ssh, run on the PC): backup updater. One ssh ControlMaster connection; `uname -m` + `getconf LONG_BIT` picks the asset (aarch64 kernel with 32-bit userland = armv7), downloads release + `.sha256` (API asset fallback on 5xx/timeout, same as `update.rs`), streams it over ssh stdin to `<dir>/.bman-update.tmp`, re-checks with `sha256sum` if present, renames over `<dir>/bman`. `--tag`, `--file`, `--dir`.

- Bump `version` in Cargo.toml, commit, tag `vX.Y.Z`, push the tag (workflow builds and publishes). Only when the owner says to push/release.
- **Every push is a release.** When the owner says "push", always bump the version, tag and push the tag too, never a plain commit push.
- Owner's versioning: small fixes = patch (0.1.x), bigger updates = minor (0.x.0). Patch never exceeds 9: the release after 0.x.9 is 0.(x+1).0, not 0.x.10 (workflow enforces it). Notes come from commit messages via `.github/release-notes.sh`: patch = commits since previous tag; x.y.0 = everything since previous x.y.0, grouped by version. So write commit messages as user-facing notes (subject + `- ` bullets); a trailing "; release X.Y.Z" in the subject is stripped.

## Design decisions (don't undo without asking)

- **One button.** Press count within 350 ms: 1 select/play/pause, 2 down, 3 up, 4 back, 5 action, hold (800 ms) help. On Now Playing for podcasts/audiobooks (`spoken::is_spoken`): 2 = +30 s, 3 = -15 s, 5 = speed (owner's choice). On Now Playing otherwise (owner's choice, matches usual players): 2 next, 3 previous (restarts if >3 s in), 5 loop mode (Off, Track, All, Random). Random = shuffle bag (`shuffle_bag` of unplayed indices, refilled without the current song when empty, so no back-to-back repeat), next pick decided up front (`shuffle_next`, so streams prefetch it), `shuffle_history` for previous; reset on queue edits other than `enqueue`. Music can be started from any screen.
- **Audio output.** `use_system_audio=false` means stereo GPIO PWM (hardware PWM, 8 kHz sample rate, 50 kHz carrier, GPIO 12 and 13, via `dtoverlay=pwm-2chan,pin=12,func=4,pin2=13,func2=4`). `true` uses rodio and is for PC testing. The Whisplay's built-in mono audio is deliberately unused. GPIO 12/13 were chosen to avoid the Whisplay's I2S pins.
- **Rescans** are throttled to one per 5 s (`RESCAN_INTERVAL`), still triggered by screen changes.
- **Library naming.** Folders `Artist - Album`, files `Artist - Album - 01 Title.ext`, singles `Artist - Title.ext`. `music/Artist/Album/` also works. Symlinks are followed (with a visited set to avoid loops). The library is rescanned on every screen change.
- **Idle.** Screen sleeps after `screen_timeout` (30-300 s, default 60; 0 or <30 = never, shown as "Never"). Music keeps playing. Waking press also acts on Now Playing if a song is playing; otherwise it only wakes. Before sleeping: dims to `SLEEP_DIM_PCT` (30%) `SLEEP_DIM_BEFORE` (5 s) ahead, fades to 0 over the last `SLEEP_FADE_OUT` (1 s) via `App::sleep_fade_pct()` scaling the brightness passed to `set_brightness` (0 allowed; below the backlight floor it's colour), frames every 30 ms while ramping; 0 while idle so the backlight never jumps up before switching off.
- **Brightness.** Hybrid: backlight software PWM on GPIO 22 down to `BACKLIGHT_MIN_PCT` (50), anything dimmer is done by scaling frame colours. Drivers without backlight control (the window) do all dimming in colour. `Display::set_brightness(percent) -> u8` returns the remaining colour-scale percentage.
- **Battery.** Top-right icon. `battery=auto` (default) tries sysfs (`/sys/class/power_supply`), then pisugar, else shows infinity; re-checked every poll. `battery=none` draws a full battery with an infinity sign. `battery=sysfs` reads the kernel battery. `battery=pisugar` reads `pisugar-server` over `/tmp/pisugar.sock` (TCP `127.0.0.1:8423` fallback). A `?` means the server wasn't reachable. The PiSugar **S** cannot report battery level; PiSugar 2/3 can.
- **Restarts keep playing.** An installed update waits for the song to change (`restart_after_song`, hooked in `play_index_from`) unless nothing is playing/paused; `restart_with_resume` writes `.bman-resume` (queue paths, index, position, paused, loop; gitignored, ignored if >10 min old) and the new process resumes it in `resume_after_restart`. Restart bman uses the same path.
- **Updates.** Never auto-install; a found update wakes the screen and opens an Update now / Not now prompt (deferred only while typing or in help); the screen can't sleep on the prompt, on System while an update is offered, or while installing; Settings > System also installs. Release tag must equal the Cargo.toml version (workflow enforces it).
- **Streaming downloads.** One yt-dlp run per song: audio (`140`), then with Videos on the video (`160/133`) into `temp/<id>.mp4`; progress lines on stdout (`--progress-template`, `--newline`) drive the Now Playing loading bar; the song plays when the audio's `after_move` line arrives, the video opens on `VideoReady`. Screen stays awake while a video plays on Now Playing (not when paused). Whole file to `temp/` before playing, deleted when not current/next, `temp/` purged at startup (crash) and exit (owner's choice). No persistent cache, no saving into `music/`.
- **Whisplay pins.** SPI0 (MOSI 10, SCLK 11, CE0 8), DC 27, RESET 4, backlight 22, button 17, LED red 25 / green 24 / blue 23 (active low, from PiSugar's `runtime/whisplay.py`). ST7789 row offset 20, RGB565, 50 MHz SPI.

## Unverified (best guesses, check on hardware)

- Whisplay ST7789 init sequence, `MADCTL`, `ROW_OFFSET`, `SPI_HZ` (PiSugar's `whisplay.py` couldn't be fetched when this was written).
- `BACKLIGHT_ACTIVE_LOW = true` polarity.
- Status LED colours/polarity on the real Whisplay (pins and active-low taken from PiSugar's `runtime/whisplay.py`).
- Backlight PWM flicker at the 50% floor.
- PiSugar server reply format (`get battery`, `get battery_charging`, `get battery_power_plugged`) for the PiSugar 3. Written from the PiSugar 2 README.
- PWM audio RC filter values (about 1 kΩ + 33 nF per channel plus a 10 µF DC-blocking cap) are an untested estimate.
- Button wiring auto-detect (don't hold the button at startup).
- Podcasts / audiobooks: tested on the PC (time-stretch unit tests, live Apple Podcasts + LibriVox search, feed subscribe/parse, m4b chapters from ffmpeg files (Nero + QuickTime), the app driven by keys: book, +30 s, speed, switching, save at exit, resume). Not tested: speakers (the PC's ALSA device errored in the pty runs), a LibriVox download played end to end, anything on the Pi (WSOLA CPU load on a Zero 2 W next to decoding, the GPIO path at speed).
- USB transfer: tested on the PC with dummy_hcd + libmtp (detect, list, 5 MB up/down, new folder, delete; the app starting it from `usb=true`) and on the Pi Zero 2 W over a real cable (owner confirmed it works). Not tested: Windows Explorer, macOS (OpenMTP), GNOME/KDE file managers, cancel mid-copy, the boot step on non-systemd inits.
- Wi-Fi: listing/IP/saved-network reading tested against NetworkManager on a PC; connect, password entry, forget and on/off not tested yet.
- Updater: check against the GitHub API tested (404 = no releases); download/install/restart and the release workflow not run yet.
- Autostart: detection and non-root refusal tested on Void (runit); writing the services as root not tested on any init.
- Bluetooth D-Bus flow tested against BlueZ 5.86 on a PC (list, power, agent, scan); actual headset pair/connect not tested yet.
- YouTube Music: setup, search, download, prefetch/kill and cleanup tested on an x86_64 PC (yt-dlp 2026.10.26, Deno 2.9.8). Liked songs (own list) tested; account likes only tested signed out ("playlist does not exist" -> *Not signed in*), not with real cookies. Music videos tested on the PC (search videos, play, pause, keep-awake). Not tested on the Pi: OpenH264 cross build (workflow) and decode speed on a Zero 2 W, aarch64 Deno, speed of yt-dlp/Deno on a Zero 2 W (512 MB RAM), playback of the m4a through the GPIO path.
